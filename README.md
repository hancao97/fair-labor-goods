按员工反馈优先开展公司调查：企业页可筛选“有员工反馈”，商品及企业档案区分本人陈述、媒体采访、企业访谈、转载和内推；资料表单允许先推荐公司。目前18家企业有27条员工资料记录，范围与局限分别展示。松下的采购、现场品质和坐便盖生产线采访按法人、岗位及年份保存，保留较少加班与周末出勤的差异。此前太阳纸业与联想武汉等经历见[办公用纸与电脑岗位核对](docs/employee-led-paper-and-electronics.md)。

此前的[办公用品员工经历](docs/office-employee-experiences.md)、[景兴员工经历与纸品](docs/jingxing-paper-employees.md)、[膳魔师商品收录](docs/thermos-employee-products.md)等批次，统一保存在[研究记录](docs/research.md)。

收录核对大陆销售、境内实际制造或服务企业及适用劳动证据，接受政府守法评级、政府综合劳动评价、可独立核实的综合劳动审核。没有额外要求固定双休、零加班、逐人考勤、实时库存或整条供应链均已核实；评价范围、年份及尚未明确的部分会逐项展示。详见[收录规则](docs/admission-standard.md)与[证据方法](docs/evidence-review-policy.md)。

研究先从员工实际工作体验筛选值得继续了解的公司，再核对劳动资料，批量对应同一主体的具体商品与购买渠道。帖子保留时间、岗位和地点，不把同一转载算成多名员工的独立反馈。评价不能借给其他法人或不在范围内的工厂。中国境内生产不能证明每位工人的国籍；项目关注境内实际劳动岗位，不收集工人身份证件或个人国籍资料。

## 功能

- 正式目录、待核查区、16 类消费清单；细分到米面油盐、蔬果肉蛋、厨房餐具、手机电脑、笔纸、汽车、住房与餐饮娱乐等。
- 商品和企业检索、中国品牌筛选、资料状态筛选、常用商品快捷查找、排序。品牌背景与生产地分别展示。
- 商品劳动档案：原始来源、发布日期、查阅日期、适用主体和例外。
- 研发、制造或外包、上游等环节分别记录，避免将总部政策扩大到整条供应链。
- 浏览器本地收藏；筛选和商品链接可分享。收藏不跨设备同步。
- 企业档案、来源资料库、JSON 下载、GitHub Issue 资料提交入口。
- 手机和桌面布局、键盘操作、原生对话框、减少动态效果设置，无 emoji。

## 本地运行

需要 Node.js 22.12 或更高版本。

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/fair-labor-goods/`。

```sh
npm run check:data
npm test
npm run build
npm run preview
```

技术栈为 React、TypeScript、Vite，图标采用 Lucide SVG。无需服务端、数据库或 API 密钥；商品图片保存在项目内，页面不依赖 Google Fonts 或外部图片加载。

## 数据维护

主数据位于 `public/data/catalog.json`。每项产品的 `admission` 分别记录大陆销售、境内生产、生产劳动证据；企业档案保留政府评价、制度与岗位来源；`coverage` 保存细分需求和研究缺口。图片来源与权利信息位于 `public/data/image-credits.json`。更新数据后同步修改 `updatedAt` 并运行检查。

资料整理日期表示人工查阅日期，不能替代内容发布日期，也不等于实际劳动条件的验证日期。旧来源、来源未知日期、不同法人和旺季例外应保留显著说明。

## GitHub Pages

`.github/workflows/pages.yml` 会在 `main` 推送后验证数据、运行单元测试、构建并发布；PR 只运行检查与构建。仓库的 Settings → Pages → Source 需设为 **GitHub Actions**。部署使用 `github-pages` 环境。

CI 自动使用仓库名称生成站点基础路径，并更新 GitHub 共建链接。仓库改名后修改本文链接与本地默认配置即可；自定义域名可通过 `PAGES_BASE_PATH=/` 构建。路由使用 hash，商品分享使用查询参数，适配 GitHub Pages 无服务端路由的环境。
